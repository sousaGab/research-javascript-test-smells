# Refactor Command Integration with Backup - Implementation Summary

## Overview

Successfully integrated the BackupManager with the refactor command to provide automatic backup and file replacement functionality. The default behavior is **dry-run mode** (safe preview), with an optional `--apply` flag to apply changes with automatic backup.

## Changes Made

**Key Modifications:**


3. **Enhanced Argument Parsing**
   - Added support for `--apply` flag in command line arguments
   - Flag can be placed anywhere in the argument list:
     - `refactor 42 --apply`
     - `refactor 42 3 1 --apply`

4. **Database Integration**
   - Extracts file path from `smell.file.path`
   - Extracts repository name from `smell.file.repository.name`
   - These are stored in the study_smells table

5. **Conditional Workflow**

   **Dry-Run Mode (Default):**
   - Calls LLM to generate refactored code
   - Displays original and refactored code
   - Shows message: "Changes NOT applied to file (dry-run mode)"
   - Suggests command to apply: `refactor <id> <strategy> <model> --apply`

   **Apply Mode (--apply flag):**
   - Calls LLM to generate refactored code
   - Displays original and refactored code
   - Validates file path and repository directory
   - Creates backup using BackupManager
   - Applies changes to the file using `replace_snippet()`
   - Displays success message with backup location
   - Provides undo command

6. **Error Handling**
   - Validates repositories directory exists
   - Validates target file exists
   - Catches and displays errors gracefully
   - Falls back to dry-run if apply fails

## Usage Examples

### Dry-Run Mode (Default - Safe)

```bash
# Preview refactoring only
llm-refactor> refactor 42
# Shows: original code, refactored code, "DRY-RUN MODE (preview only)"

# With custom strategy and model
llm-refactor> refactor 42 3 1
# Uses CoT strategy and Qwen model, shows preview only
```

### Apply Mode (Creates Backup + Applies Changes)

```bash
# Apply with default settings
llm-refactor> refactor 42 --apply
# Creates backup → applies changes → shows backup location

# Apply with custom strategy and model
llm-refactor> refactor 42 3 1 --apply
# Uses CoT, Qwen, creates backup, applies changes
```

### Complete Workflow

```bash
# 1. Preview the refactoring
llm-refactor> refactor 42
[Shows refactored code]

# 2. If satisfied, apply changes
llm-refactor> refactor 42 --apply
✓ Backup created: backup/luxon/test/parse.test.js
✓ Changes applied successfully

# 3. If needed, undo
llm-refactor> backup restore luxon test/parse.test.js
✓ File restored successfully
```

## Technical Implementation

### File Path Resolution

The implementation automatically resolves file paths from the database:

```python
# From study_smells table
file_path = smell.file.path                    # e.g., "test/parse.test.js"
repo_name = smell.file.repository.name          # e.g., "luxon"

# Construct full path
repositories_dir = Path(os.getcwd()).parent / "repositories"
full_file_path = repositories_dir / repo_name / file_path
```

### Backup and Replace Logic

When `--apply` flag is used:

```python
# 1. Validate paths
if not repositories_dir.exists():
    show_warning()
    return

# 2. Create BackupManager
backup_manager = BackupManager(str(repositories_dir))

# 3. Apply changes (automatically creates backup)
backup_path = backup_manager.replace_snippet(
    str(full_file_path),
    code_snippet,        # Original code from database
    refactored_code      # Generated by LLM
)

# 4. Show success message
print(f"✓ Backup created: {backup_path}")
print(f"✓ Changes applied successfully")
```

## Safety Features

2. **Automatic Backups**: Backup created before any file modification

4. **Error Recovery**: Graceful fallback to preview mode if apply fails
5. **Clear Messaging**: Always shows mode (DRY-RUN vs APPLY MODE)
6. **Undo Instructions**: Provides command to revert changes
